## 1. 열 정의

| 열 | 형식 | 의미 |
|---|---|---|
| `id` | 정수 | 스킬 ID. 프로토콜의 `skill_id`와 같은 값 |
| `name` | 문자열 | 이름 |
| `class` | 문자열 | 직업 |
| `target_type` | enemy / ally / self / ground | 대상 종류. ground는 지면 지정 |
| `range_cm` | 정수 | 사거리. self는 0 |
| `cast_time_ms` | 정수 | 시전 시간. 0이면 즉시 |
| `cooldown_ms` | 정수 | 쿨다운 |
| `gcd` | true / false | 전역 쿨다운을 발동하는가 |
| `cost_type` | none / mana / stamina | 자원 종류 |
| `cost` | 정수 | 자원 비용 |
| `coefficient` | 실수 | 공격력에 곱하는 계수 (타격 1회) |
| `base_damage` | 실수 | 고정 피해 (타격 1회). 없으면 0 |
| `hits` | 정수 | 타격 횟수. 없으면 1 |
| `dot_tick_ms`, `dot_duration_ms` | 정수 | 지속 피해의 간격과 지속 시간. 없으면 0 |
| `dot_coefficient` | 실수 | 지속 피해 1회의 계수 |
| `aoe_radius_cm` | 정수 | 범위 반지름. 단일 대상이면 0 |
| `max_targets` | 정수 | 범위 스킬이 맞히는 최대 대상 수 |
| `level_req` | 정수 | 습득 레벨 |
| `usable_modes` | `ground\|mounted\|fly` | 쓸 수 있는 이동 모드. `\|`로 구분 |

피해량 = (`base_damage` + `coefficient` × 공격력) × `hits` + (지속 피해 횟수 × `dot_coefficient` × 공격력)

## 2. 규칙 설명

| ID | 의미 | 왜 중요한가 |
|---|---|---|
| SKILL001 | 필수 값 누락, 숫자가 아님, ID 중복 | 서버가 0이나 기본값으로 읽으면 무료 스킬, 즉시 스킬이 된다 |
| SKILL002 | 알 수 없는 직업, 대상 종류, 자원 종류, 이동 모드 | 오타. 서버가 조건 검사를 건너뛸 수 있다 |
| SKILL003 | 사거리 오류: self인데 0이 아님, 대상이 있는데 0 이하, 최대 사거리 초과 | 최대 사거리가 서버의 관심 영역보다 크면 서버가 보지 못하는 대상을 공격하게 된다 |
| SKILL004 | 시간 오류: 음수, 시전 0·쿨다운 0·전역 쿨다운 없음, 지속 피해 간격 오류 | 세 값이 모두 0이면 한 프레임에 무한히 쓸 수 있다. 서버 부하와 피해량 폭주 |
| SKILL005 | 시전 시간, 쿨다운, 지속 피해 간격이 서버 틱의 배수가 아님 | 서버는 틱 단위로 처리한다. 배수가 아니면 표시와 실제가 어긋난다 |
| SKILL006 | 비용 오류: 음수, 자원 없음인데 비용 있음, 자원량보다 큼 | 음수 비용은 자원을 무한히 얻는 수단이 된다 |
| SKILL007 | 지면 지정인데 반지름 없음, 범위 스킬에 최대 대상 수 없음 | 대상 수 상한이 없으면 밀집 지역에서 스킬 하나가 수백 명을 계산한다 |
| SKILL009 | 직업의 DPS가 다른 직업들의 중앙값에서 허용 편차 이상 벗어남 | 확인 신호. 의도일 수 있다 |
| SKILL010 | 스킬의 시간당 피해가 같은 직업 중앙값의 몇 배 이상 | 계수나 자릿수 오타일 가능성이 높다 |
| SKILL011 | 기준 회전에서 한 번도 선택되지 않는 스킬 | 다른 스킬보다 항상 불리하다. 부가 효과가 있는 스킬이면 정상이다 |

## 3. 계산 모델

직업마다 다음을 반복한다(기본 180초, 지상 모드).

1. 지금 쓸 수 있는 스킬을 모은다: 쿨다운이 끝났고, 자원이 충분하고, 적이나 지면 대상이고, 피해가 있는 것.
2. 그중 "쓴 시간당 피해"가 가장 큰 것을 쓴다. 쓴 시간 = 시전 시간과 전역 쿨다운 중 긴 쪽.
3. 쓴 시간만큼 시계를 돌리고 자원을 회복한다.
4. 쓸 수 있는 것이 없으면 다음 쿨다운이나 자원 회복까지 기다린다.

기준 능력치(공격력, 자원량, 초당 회복량)는 `combat-config.json`의 `reference`다.
같은 입력이면 항상 같은 결과가 나온다. 난수를 쓰지 않는다.

## 4. 모델의 한계

들어 있지 않은 것:

- 범위 스킬이 여러 대상을 맞히는 이득 (대상 하나로 계산한다)
- 버프, 디버프, 치명타, 방어력, 속성 상성
- 지속 피해를 지속 시간이 끝나기 전에 다시 걸 때의 낭비
- 이동, 거리 유지, 시전 중 방해
- 플레이어가 실제로 쓰는 회전 (모델은 탐욕적으로 고른다)

그래서 이 계산은 "직업 A가 B보다 강하다"의 근거가 아니다. 쓰임새는 세 가지다:
자릿수 오타 찾기, 쓸 이유가 없는 스킬 찾기, 큰 불균형의 조기 경보.

## 5. 데이터 설계 원칙

- **수치는 전부 서버 데이터다.** 클라이언트는 같은 표를 표시용으로만 읽는다. 클라이언트가 계산한
  피해량을 서버가 받지 않는다(`mmo-protocol-check`의 PROTO004).
- **모든 스킬은 연속 사용을 막는 장치가 하나 이상 있다.** 시전 시간, 쿨다운, 전역 쿨다운 중 하나.
- **시간 값은 서버 틱의 배수로 적는다.**
- **범위 스킬은 최대 대상 수를 반드시 적는다.** 공성전에서 서버 비용의 상한이 된다.
- **사거리는 관심 영역 안으로 잡는다.** 최대 사거리 + 허용 오차가 서버가 대상을 보는 거리보다 작아야 한다.
- **이동 모드별 사용 가능 여부를 데이터로 둔다.** 탑승 중, 비행 중에 쓸 수 있는 스킬을 코드 분기로
  정하지 않는다.
- **전역 쿨다운을 발동하지 않는 스킬은 드물게 둔다.** 이동기, 방어기처럼 반응용으로만 쓴다.

## 6. 확장 지점

- **새 직업:** CSV에 행을 추가한다. `combat-config.json`의 `classes`에 이름을 넣으면 오타를 잡아 준다.
- **새 자원 종류(분노, 기력):** `cost_types`에 추가한다. 스킬을 쓸 때 쌓이는 자원은 현재 모델에 없으므로
  DPS 계산에서 그 직업은 참고만 한다.
- **새 이동 모드에서의 전투:** `modes`에 추가하고 `sim_mode`를 바꿔 돌리면 그 모드에서의 DPS가 나온다.
  예: 탑승 전투의 피해량이 지상의 몇 퍼센트인지.
- **새 규칙:** `check_skills.py`의 `check()`에 추가하고 테스트를 붙인다.
