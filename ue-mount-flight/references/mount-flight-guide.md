## 1. 이동 컴포넌트 선택

| | Character Movement Component (CMC) | Mover |
|---|---|---|
| 5.8 상태 | 안정 | Experimental. 버전 사이에 API가 바뀐다 |
| 구조 | 걷기, 낙하, 수영, 비행이 한 클래스에 들어 있다. 커스텀 모드를 추가할 수 있다 | 이동 모드를 독립된 조각으로 조립한다. 캐릭터가 아닌 것(탈것)에도 쓰기 쉽다 |
| 애니메이션 | Motion Matching과 함께 쓸 수 있다 | Epic의 Game Animation Sample이 Mover와 Motion Matching을 함께 쓴다 |
| 방향성 | 현재의 표준 | UE6 방향. UAF 연동 플러그인도 Experimental로 들어 있다 |
| 위험 | 큰 클래스를 상속해 고치게 된다 | 5.8에서도 버그 보고와 API 변경이 이어진다 |

판단 기준:

- 자체 서버라서 두 컴포넌트의 내장 네트워크 예측은 어느 쪽도 쓰지 않는다. 비교에서 제외한다.
- 출시 일정이 UE6 이전이면 CMC가 안전하다. UE6로 옮길 계획이면 Mover를 평가할 가치가 있다.
- 어느 쪽이든 **게임 코드는 이동 컴포넌트를 직접 부르지 않고 자체 인터페이스(모드 전환 요청, 현재 모드
  조회, 속도 한계 조회)를 거친다.** 이렇게 해 두면 나중에 교체할 수 있다.

### 이 프로젝트의 결정: CMC

규약의 이동 모드를 CMC의 이동 모드에 대응시킨다.

| 규약 모드 | CMC 이동 모드 | 비고 |
|---|---|---|
| ground | Walking, 공중에 뜨면 Falling | 점프와 낙하는 ground 안의 상태로 본다 |
| swim | Swimming | 물 볼륨 진입으로 전환 |
| fly | Flying | 중력이 적용되지 않는다. 고도 한계와 뱅킹은 직접 구현한다 |
| glide | Custom | 낙하 속도를 제한하고 전진 속도를 주는 커스텀 모드로 만든다 |

- 새 이동 방식은 Custom 모드의 하위 번호로 추가한다. 규약 모드 이름과 하위 번호의 대응표를 한곳에 둔다.
- 탈것도 CMC를 쓰는 캐릭터 클래스로 만든다. CMC는 세로로 선 캡슐 하나를 충돌체로 쓰므로, 몸이 긴
  네발 탈것은 캡슐이 몸 전체를 덮지 못한다. 캡슐은 이동용으로만 쓰고, 몸통이 벽을 뚫는 문제는
  캡슐 반지름과 카메라, 추가 충돌 검사로 다룬다. 큰 탈것일수록 좁은 길에서 문제가 드러난다.
- CMC의 내장 네트워크 보정은 쓰지 않는다. 내 캐릭터는 로컬에서 CMC로 움직이고 서버 보정을 직접
  적용한다. 다른 플레이어의 캐릭터는 CMC 시뮬레이션 없이 받은 위치를 보간해 움직이는 편이 싸다.
- 자체 인터페이스 뒤에 두었으므로, UE6로 옮길 때 Mover를 다시 평가할 수 있다.

## 2. 이동 모드 설계

이동 방식을 코드 분기가 아니라 데이터로 정의한다. 규약의 `movement_modes`가 그 정의다.

| 모드 | 필요한 것 | 발 IK | 갈 수 있는 모드 |
|---|---|---|---|
| ground | 걷기, 달리기, 점프, 낙하, 착지 | 켬 | swim, glide, fly |
| swim | 수영 대기, 수영 이동 | 끔 | ground |
| glide | 활공 시작, 활공, 착지 | 끔 | ground |
| fly | 이륙, 비행 대기, 비행 이동, 착륙 | 끔 | ground |

- 모드마다 속도, 가속, 회전 한계를 데이터로 둔다. 서버가 같은 값을 써서 검증한다.
- 전환은 조건(높이, 수심, 스태미나, 지역, 날씨)을 서버가 확인하고 승인한다.
- 캐릭터와 탈것은 "쓸 수 있는 모드 목록"만 가진다. 그리핀은 ground와 fly, 말은 ground.
- 모든 모드는 기본 모드에서 갈 수 있고 기본 모드로 돌아올 수 있어야 한다(`LINK006`).

## 3. 탑승 구조

- **탈것은 자기 스켈레톤과 애니메이션을 가진 별도 액터다.** 캐릭터 메시를 바꿔 끼우는 방식은
  탈것마다 캐릭터 애니메이션을 다시 만들어야 해서 확장되지 않는다.
- **이동의 주체는 탈것이다.** 탑승 중에는 탈것의 이동 모드가 적용되고, 캐릭터는 좌석 소켓에 붙어
  탑승 애니메이션을 재생한다. 캐릭터 자신의 이동과 충돌은 끈다.
- **좌석:** 좌석마다 소켓, 탑승자 애니메이션 세트, 손발 IK 소켓을 둔다. 2인승은 좌석을 하나 더 둔다.
- **탑승자 자세:** 탈것의 상태 변화에 맞춰 탑승자도 대응 상태를 재생한다(`ride_idle`, `ride_fly`).
  손은 고삐, 발은 등자에 IK로 붙인다.
- **파츠와의 관계:** 탈것과 겹치는 탑승자 부위는 탈것이 숨긴다(`rider_hidden_slots`).
  탈것의 장식도 파츠로 만들 수 있다(`ue-character-parts`).
- **이펙트:** 발굽 먼지, 날개 궤적은 탈것 소켓에 붙이고 모드별로 켠다(`mounts.vfx`의 `mode`).
- **타고 내리기:** 탑승/하차 애니메이션 동안의 위치 보정, 하차할 자리가 없을 때(벽, 절벽)의 처리,
  전투 중 강제 하차를 정한다.
- **카메라:** 탈것 크기와 모드에 따라 거리와 시야를 바꾼다. 비행 중에는 더 멀리 둔다.

## 4. 비행 흐름

```
지상 ──(이륙 요청, 서버 승인)──► 이륙 ──► 비행 ──(착륙 요청 또는 강제 착륙)──► 착륙 ──► 지상
```

- **이륙:** 머리 위 공간을 검사한다. 실내와 비행 금지 구역에서는 거부한다.
- **비행:** 선회할 때 몸을 기울인다(뱅킹). 상승/하강 각도와 최고 고도에 한계를 둔다.
- **착륙:** 지면까지의 거리와 경사를 검사한다. 착륙할 수 없는 곳이면 가까운 가능 지점으로 유도한다.
- **강제 착륙:** 스태미나 소진, 날씨, 금지 구역 진입, 전투 피격. 규약의 날씨 `blocked_modes`가 비행을
  막을 때, 비행 중인 플레이어가 내려올 전환이 있어야 한다(`LINK010`).
- **IK:** 이륙에서 발 IK를 서서히 끄고 착륙에서 서서히 켠다.
- **월드에 주는 부담:** 빠른 비행은 월드 스트리밍을 앞지른다. 최고 속도는 스트리밍이 따라오는 범위로
  정하고, `ue-perf-budget-check`의 필드 이동 장면을 비행 최고 속도로 측정한다.
- **보이는 것:** 높은 곳에서는 먼 지형의 저해상도 표현과 배치 밀도의 끝이 드러난다(`ue-environment-worldbuilding`).

## 5. 서버 연동

- 클라이언트는 입력과 예측 위치를 보낸다. 서버는 모드별 속도 한계, 고도 한계, 금지 구역으로 검증한다.
- 모드 전환은 요청-승인이다. 클라이언트가 먼저 연출을 시작했다가 거부되면 되돌린다.
- 서버의 내비메시는 지면만 다룬다. 공중 이동 검증과 비행 몬스터의 길 찾기는 별도 방법이 필요하다
  (고도 범위, 금지 볼륨, 간단한 3차원 격자).
- 탑승 상태(누가 어느 탈것의 몇 번 좌석에)는 서버가 관리하고 주변 플레이어에게 알린다.
- 패킷 정의는 `mmo-protocol-check`, 핸들러 검증은 `mmo-netcode-review`의 체크리스트를 따른다.

## 6. 확장 지점

| 하고 싶은 것 | 필요한 것 |
|---|---|
| 새 지상 탈것 | 탈것 스켈레톤, 세트, IK 프로필, 좌석 소켓, 탑승자 세트. 코드 변경 없음 |
| 기존 탈것에 비행 추가 | 탈것의 모드 목록에 fly. 검사기가 빠진 비행 상태와 탑승자 상태를 알려 준다 |
| 새 이동 모드 (잠수, 벽 타기) | 규약에 모드 추가, 이동 로직 구현 1개, 서버 검증 규칙 1개 |
| 다인승 탈것 | 좌석 추가. 좌석마다 조종 가능 여부를 둔다 |
| 탈것 위 전투 | 탑승 세트 위에 상체 스킬 레이어. 모드별로 쓸 수 있는 스킬을 데이터로 제한 |
| 변신(캐릭터가 직접 비행) | 탈것 없이 캐릭터의 모드 목록에 fly 추가. 같은 규약과 검사를 쓴다 |

## 7. 체크리스트

- [ ] 게임 코드가 이동 컴포넌트를 직접 부르지 않고 자체 인터페이스를 거친다
- [ ] 모드별 속도와 한계가 데이터에 있고 서버와 같은 값을 쓴다
- [ ] 모드 전환이 서버 승인을 거친다
- [ ] 탑승 중 캐릭터의 이동과 충돌이 꺼진다
- [ ] 하차할 자리가 없을 때의 처리가 있다
- [ ] 비행 중 강제 착륙 경로가 모든 원인(날씨, 스태미나, 구역)에 대해 있다
- [ ] 비행 최고 속도로 스트리밍 히치를 측정했다
- [ ] 규약 검사(`ue-client-contract`)를 통과했고 연결 표를 확인했다
