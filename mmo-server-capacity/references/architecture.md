# MMORPG 서버 구조 가이드

서버 구조를 설계하거나 질문에 답할 때 읽는다. 여기 적힌 것은 선택지와 판단 기준이다.
프로젝트가 실제로 고른 것은 `mmorpg-router/references/project-context.md`에 기록한다.

## 목차

1. 먼저 정해야 할 것
2. 월드 구성 방식
3. 구성 요소
4. 영속성(저장)
5. 사람이 몰리는 상황
6. 계산 모델과 한계

## 1. 먼저 정해야 할 것

아래가 정해지지 않으면 넷코드, 콘텐츠, 비용 계획이 모두 흔들린다. 미정이면 미정이라고 밝히고 답한다.

- 목표 동시 접속자 수(전체, 월드 하나, 한 장소)
- 월드가 끊김 없이 이어지는가, 존 단위로 로딩이 있는가
- 게임 서버를 언리얼 데디케이티드 서버로 만드는가, 자체 서버로 만드는가
- 대규모 전투(공성전 등)의 목표 인원

## 2. 월드 구성 방식

| 방식 | 설명 | 장점 | 부담 |
|---|---|---|---|
| 서버군(샤드) 분리 | 같은 월드를 여러 벌 운영하고 플레이어는 한 곳에 속한다 | 구조가 단순하다 | 서버군 사이에 친구, 경제가 갈린다 |
| 존 분할 | 월드를 지역으로 나눠 지역마다 서버 프로세스를 둔다. 붐비면 같은 지역을 채널로 복제한다 | 지역별로 확장된다. 언리얼 서버와 잘 맞는다 | 존 이동 처리, 채널 간 만남 문제 |
| 단일 월드 | 모두가 한 월드에 있고 서버 경계를 숨긴다 | 하나의 경제와 사회 | 경계에서의 권한 이전, 부하 분산을 직접 만들어야 한다 |

언리얼 데디케이티드 서버는 프로세스 하나가 맵 하나를 담당하는 구조다. 그래서 존 분할이 가장
자연스럽고, 단일 월드는 서버 사이를 잇는 계층을 따로 만들거나 구해야 한다.

## 3. 구성 요소

- **존 서버:** 언리얼 데디케이티드 서버. 전투, 이동, NPC 등 실시간 시뮬레이션만 담당한다.
- **게이트웨이/인증:** 로그인, 세션 토큰, 접속할 존 서버 안내.
- **월드 서비스:** 어느 캐릭터가 어느 존에 있는지, 존 이동, 채널 배정.
- **인스턴스 관리:** 던전 서버 프로세스를 띄우고 내린다.
- **소셜 서비스:** 채팅, 파티, 길드, 친구, 우편. 존을 넘나들므로 존 서버 밖에 둔다.
- **경제 서비스:** 경매장, 거래, 결제. 트랜잭션과 감사 로그가 필요하다.
- **데이터베이스:** 캐릭터, 인벤토리, 진행도.
- **운영 도구:** 로그, 지표, GM 도구, 점검/패치 배포.

존 서버가 죽어도 소셜, 경제, 저장 데이터는 살아 있어야 한다. 이 기준으로 경계를 긋는다.

## 4. 영속성(저장)

- 존 서버가 DB에 직접 동기 쿼리를 날리지 않는다. 게임 스레드가 멈춘다. 비동기 요청이나 중간 서비스를 둔다.
- 저장 시점을 정한다: 주기 저장, 중요 사건 즉시 저장(거래, 결제, 희귀 아이템 획득), 로그아웃 저장.
- 아이템 복사를 막는다. 거래와 우편은 양쪽 변경을 하나의 트랜잭션으로 묶는다. 존 이동 중에는
  캐릭터 데이터의 소유 서버가 항상 하나여야 한다.
- 재화와 아이템의 생성/소멸을 전부 로그로 남긴다. 경제 이상을 찾는 유일한 방법이다.

## 5. 사람이 몰리는 상황

평균이 아니라 최악을 기준으로 설계한다.

- 서버 쪽: 보이는 플레이어 수 상한, 거리별 갱신 빈도, 채널 분산, 정원 초과 시 대기열.
- 클라이언트 쪽: 먼 캐릭터의 애니메이션 갱신 빈도 낮추기, LOD, 이펙트 수 제한, 이름표 수 제한.
  클라이언트 예산은 `ue-perf-budget-check`로 밀집 장면을 따로 측정한다.
- 콘텐츠 쪽: 한 지점에 모이게 만드는 설계(단일 NPC, 단일 포털)를 피한다.

## 6. 계산 모델과 한계

`scripts/capacity_calc.py`의 모델:

- 클라이언트 수신량 = (보이는 플레이어 × 갱신 빈도 × 갱신 크기) + (보이는 NPC × 갱신 빈도 × 갱신 크기) + (전송 빈도 × 패킷 헤더)
- 서버 송신량 = 클라이언트 수신량 × 서버 인원
- 서버 수 = 올림(동시 접속 ÷ 서버 정원), 여기에 여유분을 곱한다
- 월 송신량 = 평균 상황 수신량 × 평균 동시 접속 × 한 달

모델에 없는 것: 서버 CPU 비용(이동, AI, 물리), 스킬/버프 이벤트 폭주, 압축과 델타 전송 효과,
채팅 등 다른 서비스 트래픽. 서버 정원(`players_per_server_cap`)은 계산 결과가 아니라 입력이다.
이 값은 봇을 붙인 부하 테스트로만 알 수 있다.
