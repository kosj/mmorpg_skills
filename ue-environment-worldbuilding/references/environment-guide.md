## 1. 기술 선택

| 기술 | 5.8 상태 | 내용 | 판단 |
|---|---|---|---|
| Landscape | 안정 | 높이맵 기반 지형 | 본 제작의 기본 |
| Mesh Terrain | Experimental | 3D 메시 기반 지형. 돌출부, 떠 있는 섬, 터널을 만들 수 있고 PCG, Nanite, 버추얼 텍스처와 함께 동작한다 | 동굴이나 공중 지형이 핵심이면 평가한다. 본 제작 전체를 걸지 않는다 |
| Nanite | 안정 | 고밀도 메시 | 바위, 건물, 지형 장식의 기본. LOD를 따로 만들지 않아도 된다 |
| Nanite Foliage | 사용 가능 | 인스턴싱, GPU 기반 스켈레탈 애니메이션, 원거리 복셀 표현 | 숲 규모의 식생 |
| Procedural Vegetation Editor (PVE) | Experimental | 에디터 안에서 Nanite용 식생을 만들고 바람에 반응시킨다 | 5.7에서 만든 PVE 에셋이 5.8에서 열리지 않았다. 버전 변경 위험을 감안한다 |
| PCG | 사용 가능 | 규칙 기반 배치. 5.8에서 절차적 결과를 직접 수정해도 규칙이 유지된다 | 숲, 바위, 풀, 길가 소품의 기본 배치 방법 |
| World Partition, HLOD | 안정 | 격자 스트리밍과 원경 대체 메시 | 오픈 필드의 기본 |
| MegaLights | Production-Ready | 다수의 동적 라이트 | 마을과 던전의 조명 |
| Lumen Lite | 5.8 신규 | 성능 위주의 전역 조명 | 60fps 목표에서 Lumen 고품질 대신 검토 |

UE 5.8은 UE5의 마지막 주요 버전으로 예고되었다. Experimental 기능은 UE6에서 형태가 바뀔 수 있다.

## 2. 에셋 제작 규칙

- **모듈화:** 건물과 성벽은 격자에 맞는 조각으로 만든다. 조각 크기를 프로젝트에서 하나로 정한다.
- **재사용:** 바위와 절벽은 여러 방향에서 다르게 보이도록 만들어 회전과 크기 변화로 재사용한다.
- **머티리얼:** 배경 머티리얼은 날씨용 공통 함수(젖음, 눈 쌓임)를 포함한다(`ue-weather`).
  머티리얼 수를 줄이고 인스턴스로 변형한다.
- **충돌:** 플레이어가 닿는 에셋만 단순 충돌을 넣는다. 풀과 작은 소품은 충돌을 뺀다.
  서버는 단순화한 충돌만 쓰므로, 통과 여부가 중요한 것은 단순 충돌로 표현되어야 한다.
- **규격:** 이름, 텍스처 크기, 삼각형 수, 머티리얼 슬롯은 `ue-asset-spec-check`의 기준을 따른다.
- **식생:** 바람 반응을 넣는다. 전역 바람 값은 날씨가 정한다.

## 3. 배치 방법

| 대상 | 방법 |
|---|---|
| 지형의 큰 형태 | 손으로. 플레이 동선과 시야가 걸려 있다 |
| 숲, 풀, 바위, 덤불 | PCG. 경사, 고도, 물과의 거리, 바이옴 마스크로 규칙을 만든다 |
| 길과 길가 소품 | PCG와 스플라인 |
| 마을, 퀘스트 거점, 랜드마크 | 손으로. 필요하면 PCG 결과를 직접 수정한다(5.8) |
| 전투 공간 | 손으로. 시야를 가리는 식생과 걸리는 소품을 뺀다 |

- 바이옴마다 레이어(에셋과 밀도)를 데이터로 둔다. 규약의 `biomes.layers`가 그것이고, 밀도 합에 예산을 건다.
- 밀도는 100m²당 개수로 적는다. Nanite가 아닌 에셋은 낮은 상한을 따로 둔다.
- PCG 규칙에는 제외 조건을 넣는다: 길, 건물 주변, 스폰 지점, 채집물 위치, 퀘스트 오브젝트.
- 배치는 재현 가능해야 한다. 같은 시드로 다시 생성하면 같은 결과가 나오게 하고, 손으로 고친 부분은
  규칙과 분리해 보존한다.

## 4. 스트리밍과 원경

- World Partition 격자 크기와 로딩 거리는 이동 속도가 정한다. 탈것과 비행의 최고 속도로 달렸을 때
  스트리밍이 따라오는지 측정한다(`ue-mount-flight`, `ue-perf-budget-check`의 필드 이동 장면).
- HLOD는 비행 높이에서 본 모습으로 검수한다. 지상에서는 보이지 않던 원경의 빈 곳과 팝핑이 드러난다.
- 풀처럼 가까이서만 보이는 레이어는 짧은 거리에서 끈다. 나무와 큰 바위는 멀리까지 유지한다.
- 마을은 플레이어가 몰리는 곳이다. 배경 비용을 필드보다 낮게 잡아 캐릭터에게 예산을 남긴다.

## 5. 서버 데이터 동기화

자체 서버는 언리얼 맵을 읽지 못한다. 배치가 바뀌면 다음이 어긋날 수 있다.

| 클라이언트에서 바뀐 것 | 서버에 필요한 것 |
|---|---|
| 지형 높이, 절벽, 다리 | 내비메시와 높이 데이터 재생성 |
| 건물, 큰 바위(통과 불가) | 충돌 데이터 재생성 |
| 스폰 지점, 채집물, 트리거 볼륨 | 위치 데이터 내보내기 |
| 비행 금지 구역, 안전 지대 | 구역 데이터 내보내기 |

- 맵을 저장할 때 내보내기가 자동으로 돌게 한다. 손으로 하면 반드시 빠진다.
- 내보낸 데이터에 맵 버전을 기록하고, 서버와 클라이언트가 접속 시 비교한다.
- PCG로 생성한 통과 불가 오브젝트도 내보내기에 포함되는지 확인한다.
- 내보내기와 버전 검사는 `ue-server-data-export` 스킬로 한다.

## 6. 다른 시스템과의 연결

- **날씨:** 바이옴이 허용 날씨를 정한다. 식생은 바람에, 표면은 젖음과 눈에 반응한다.
- **탈것과 비행:** 지형의 경사 한계가 탈것이 갈 수 있는 곳을 정한다. 비행은 원경 품질과 스트리밍을 시험한다.
- **IK:** 계단과 바위의 단차가 발 IK의 보정 범위 안이어야 한다. 너무 높은 단차는 발이 뜬다.
- **VFX:** 폭포, 횃불 같은 배치 이펙트는 ambient 분류로 거리에서 끈다.
- **기획 데이터:** 스폰 지점과 채집물의 ID는 기획 데이터와 같은 것을 쓴다(`mmo-data-check`).

## 7. 확장 지점

- **새 지역:** 바이옴을 추가하고 레이어와 허용 날씨를 적는다. 기존 PCG 규칙을 바이옴 마스크만 바꿔 재사용한다.
- **새 식생 종:** 에셋을 만들어 바이옴 레이어에 추가한다. 밀도 예산 초과는 검사기가 알려 준다.
- **계절이나 이벤트 변형:** 레이어 세트를 바꿔 다시 생성한다. 충돌이 바뀌면 서버 데이터도 다시 내보낸다.
- **지하나 공중 지역:** Landscape로 표현되지 않으면 메시로 만든다. Mesh Terrain은 평가 후 결정한다.

## 8. 체크리스트

- [ ] 에셋이 `ue-asset-spec-check`를 통과했다
- [ ] 배경 머티리얼이 날씨 공통 함수를 쓴다
- [ ] 통과 여부가 중요한 에셋에 단순 충돌이 있다
- [ ] PCG 규칙에 길, 건물, 스폰 지점 제외 조건이 있다
- [ ] 바이옴 밀도가 예산 안이다 (규약 검사 통과)
- [ ] 탈것/비행 최고 속도로 스트리밍 히치를 측정했다
- [ ] 비행 높이에서 원경을 검수했다
- [ ] 배치 변경 후 서버용 데이터를 다시 내보냈다
