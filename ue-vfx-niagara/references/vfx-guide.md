## 1. 분류와 예산

| 분류 | 예 | 수명 | 우선순위 |
|---|---|---|---|
| skill | 스킬 시전, 투사체, 장판 | 짧음 | 내 것 > 파티 > 나를 노리는 적 > 그 외 |
| hit | 피격, 타격 불꽃 | 매우 짧음 | 수가 많다. 가장 먼저 줄인다 |
| part | 불타는 망토, 얼음 검 | 장착 중 계속 | 가까운 캐릭터만 |
| mount | 발굽 먼지, 날개 궤적 | 탑승 중, 모드별 | 가까운 탈것만 |
| weather | 비, 눈, 번개 | 날씨 지속 | 화면에 하나. 카메라를 따라간다 |
| ambient | 횃불, 폭포, 반딧불 | 배치되어 계속 | 거리로 끈다 |

규약의 `vfx.cost`는 프로젝트가 정하는 예산 점수다. 처음에는 "동시에 살아 있는 파티클 수와 화면을
덮는 정도"를 기준으로 1~10으로 매기고, 측정값이 쌓이면 조정한다. 파츠와 탈것에는 합계 상한을 둔다.

## 2. 확장성 설정

- **Niagara Effect Type:** 분류마다 Effect Type 에셋을 하나 만들고 모든 시스템에 지정한다. 스폰 한계,
  거리에 따른 정지와 제거, 품질 단계별 스폰 배율을 여기서 정한다. 시스템마다 따로 설정하지 않는다.
- **중요도:** 한계를 넘었을 때 무엇을 남길지 정하는 기준(거리, 내 것 여부)을 Effect Type에 둔다.
- **품질 단계:** 그래픽 옵션과 연결한다. 낮은 단계에서 파티클 수를 줄이고 일부 이미터를 끈다.
- **고정 범위:** 시스템의 경계 상자를 고정한다. 매 프레임 계산하지 않게 한다.

## 3. 생성 방식

| 방식 | 맞는 용도 |
|---|---|
| 시스템을 풀에서 꺼내 생성 | 스킬, 파츠, 탈것 이펙트. 생성과 제거 비용을 없앤다 |
| Niagara Data Channel | 피격, 발자국, 탄착처럼 작고 많은 이벤트. 이벤트마다 시스템을 만들지 않고, 미리 떠 있는 시스템 하나에 위치와 값을 써 넣는다 |
| 레벨에 배치 | ambient. 거리로 켜고 끈다 |

- CPU 시뮬레이션: 수가 적고 게임과 상호작용(충돌 이벤트)이 필요한 것.
- GPU 시뮬레이션: 수가 많은 것(비, 눈, 대형 장판).
- Niagara Fluids(연기, 물 시뮬레이션): 5.8에서 속도가 개선되었다는 제작자 보고가 있다. 보스 연출처럼
  화면에 하나만 나오는 곳에 쓰고, 플레이어 스킬처럼 여러 개가 동시에 나오는 곳에는 쓰지 않는다.

## 4. 부착 규칙

- 부착 이펙트는 소켓 이름으로 붙인다. 본 이름이나 오프셋 숫자를 코드에 적지 않는다.
- 파츠에 붙는 이펙트는 파츠가 제공하는 소켓에 붙인다(`provides_sockets`). 파츠를 벗으면 이펙트도 사라진다.
- 탈것 이펙트는 모드별로 켠다. 날개 궤적은 비행 모드에서만(`mounts.vfx`의 `mode`).
- 부착 이펙트는 풀링을 켠다. 장착과 탑승은 자주 바뀐다.
- 월드에 고정되는 이펙트(비, 장판)를 소켓에 붙이지 않는다. 검사기의 `LINK008`이 잡는다.
- 주인이 숨겨지면(은신, 탑승 시 부위 숨김) 이펙트도 함께 숨긴다.

## 5. 다수 플레이어 대응

- **다른 플레이어의 이펙트를 단계적으로 줄인다.** 전체 표시, 간략 표시, 숨김. 옵션으로 고를 수 있게 하고,
  사람이 많아지면 자동으로 낮춘다.
- **피격 이펙트에 초당 상한을 둔다.** 같은 대상에게 짧은 시간에 여러 번 맞으면 하나로 합친다.
- **게임 정보를 담은 이펙트는 줄이지 않는다.** 보스 장판, 위험 범위 표시는 항상 보여야 한다.
  분류를 따로 두거나 중요도를 최상으로 준다.
- **겹쳐 그리기(오버드로)를 줄인다.** 화면을 덮는 반투명 파티클 여러 겹이 GPU 비용의 대부분이다.
  큰 파티클 수를 제한하고 가까이 오면 사라지게 한다.
- **조명:** 이펙트의 라이트는 그림자를 끄고 수를 제한한다. MegaLights가 5.8에서 Production-Ready가
  되어 많은 라이트를 쓰기 쉬워졌지만, 대규모 전투에서의 비용은 측정으로 확인한다.

## 6. 제작 규칙

- 이름: `NS_<분류>_<이름>` (시스템), `NE_<이름>` (이미터). `ue-asset-spec-check`의 접두사 규칙을 따른다.
- 텍스처는 아틀라스로 묶고 크기를 제한한다.
- 반복 재생 이펙트는 끝과 시작이 이어지게 만든다.
- 색과 크기는 파라미터로 열어 둔다. 속성(불, 얼음)만 다른 이펙트를 복제해서 만들지 않는다.

## 7. 확장 지점

- **새 속성의 무기 이펙트:** 같은 시스템에 파라미터 세트를 추가한다.
- **새 파츠 이펙트:** 규약의 `vfx`에 등록하고 파츠에 연결한다. 예산 초과는 검사기가 알려 준다.
- **새 이동 모드 이펙트:** 탈것 `vfx`에 `mode`를 지정해 추가한다.
- **새 날씨:** 날씨 이펙트를 `vfx`에 등록하고 `weather.vfx`에 연결한다(`ue-weather`).

## 8. 체크리스트

- [ ] 분류가 정해져 있고 해당 Effect Type이 지정되어 있다
- [ ] 경계 상자가 고정되어 있다
- [ ] 풀링을 쓴다 (부착, 스킬)
- [ ] 작고 많은 이벤트는 Data Channel로 처리한다
- [ ] 거리와 품질 단계에 따라 줄어든다
- [ ] 다른 플레이어의 이펙트 표시 단계를 지원한다
- [ ] 게임 정보를 담은 이펙트가 줄어들지 않는다
- [ ] 대규모 전투 장면에서 GPU 시간을 측정했다
- [ ] 부착 이펙트는 규약 검사(`ue-client-contract`)를 통과했다
