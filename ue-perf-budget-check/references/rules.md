# 규칙 설명과 원인 좁히기

수치는 모두 `perf-budget.json`에서 온다. 60fps의 프레임 예산은 1000 / 60 = 16.67ms다.

| ID | 의미 | 실패했을 때 다음 단계 |
|---|---|---|
| PERF001 | 평균 프레임 시간이 예산을 넘는다 | 추정 병목(게임 스레드/렌더 스레드/GPU)을 보고 해당 항목으로 이동 |
| PERF002 | 가장 느린 1% 프레임이 너무 느리다 (체감 끊김) | 느린 구간이 특정 장소/이벤트인지 CSV의 프레임 번호로 확인 |
| PERF003 | 예산을 넘는 프레임이 너무 많다 | 평균은 통과인데 이 규칙만 실패면 구간별 편차가 큰 것. 구간을 나눠 다시 캡처 |
| PERF004 | 2프레임 이상 멈추는 히치가 잦다 | 로딩/스트리밍, 가비지 컬렉션, 셰이더(PSO) 컴파일, 액터 대량 스폰을 의심. Unreal Insights로 해당 시점 확인 |
| PERF010 | 게임 스레드가 느리다 | 틱 비용, 블루프린트, 애니메이션, 물리, AI. `stat game`, Unreal Insights의 CPU 타이머로 확인 |
| PERF011 | 렌더 스레드가 느리다 | 드로우 콜 수, 가시성 계산, 그림자 캐스터 수. PERF020과 함께 본다 |
| PERF012 | GPU가 느리다 | 해상도, 라이팅(Lumen/MegaLights), 그림자, 반투명, 포스트 프로세스. `stat gpu`나 `ProfileGPU`로 패스별 확인 |
| PERF020 | 드로우 콜이 많다 | 인스턴싱, 머티리얼 슬롯 수(에셋 규격 SM004), HLOD, 컬링 거리 |
| PERF030 | 메모리 사용량이 많다 | 텍스처 스트리밍 풀, 텍스처 크기(에셋 규격 TEX002), 로드된 레벨 수 |
| PERF900 | 기준(baseline) 대비 나빠졌다 | 두 빌드 사이의 변경 내역을 확인. 측정 조건이 같았는지 먼저 확인 |
| GEN001 | CSV에 해당 열이 없어 건너뜀 | 보고서의 비슷한 열 이름을 `perf-budget.json`의 `columns`에 추가 |
| GEN002 | 프레임 수가 부족 | 더 길게 캡처 |

## 통계 정의

- `avg`: 평균. `p95`/`p99`: 백분위(선형 보간). `max`/`min`: 최대/최소.
- `pct_over`: `over` 값을 넘는 프레임의 비율(%).
- 1% low fps: 1000 / (프레임 시간 p99).
- 워밍업 프레임(`warmup_frames`)은 모든 통계에서 제외한다.

## 규칙 추가 방법

`perf-budget.json`의 `rules`에 한 줄 추가하면 된다. 코드 수정은 필요 없다.

```json
{"id": "PERF021", "label": "RHI 스레드 p95", "columns": ["RHIThreadTime"], "stat": "p95", "max": 8.0, "unit": "ms", "severity": "warning"}
```

`columns`에는 후보 이름을 여러 개 적을 수 있고, 먼저 찾은 열을 쓴다.
대소문자는 구분하지 않으며, `Category/Name` 형태의 열은 `Name`만 적어도 찾는다.
