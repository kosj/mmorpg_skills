# 규칙 설명과 스키마 작성법

| ID | 의미 | 왜 중요한가 |
|---|---|---|
| DATA001 | 스키마에 있는 파일이 없다 | 빌드에 데이터가 빠진다 |
| DATA002 | 필요한 열이 없다 | 열 이름이 바뀌면 로더가 기본값을 조용히 넣는 경우가 있다 |
| DATA003 | 키가 중복된다 | 뒤 행이 앞 행을 덮어써 아이템이나 몬스터가 사라진다 |

## 스키마 작성법

`data-schema.json`의 `tables`에 테이블을 추가한다. 코드 수정은 필요 없다.

```json
"quests": {
  "file": "quests.csv",
  "key": "id",
  "columns": {
    "id": {"type": "int", "min": 1, "required": true},
    "prev_quest": {"type": "int", "ref": "quests.id", "ref_allow": [0]},
    "reward_items": {"type": "int", "ref": "items.id", "sep": "|"}
  }
}
```

### 열 옵션

- `type`: `int`, `float`, `str`, `bool`
- `required`: 빈 값을 허용하지 않는다
- `min`, `max`: 숫자 범위
- `values`: 허용 값 목록
- `ref`: `"테이블.열"`. 값이 그 열에 있어야 한다. 자기 테이블도 가능하다
- `ref_allow`: 참조 검사를 건너뛸 값. "없음"을 뜻하는 0 등
- `sep`: 한 칸에 여러 값을 넣을 때의 구분자. 각 값에 위 검사를 모두 적용한다

### 테이블 검사(`checks`)

- `{"type": "sum", "group_by": "A", "column": "B", "max": 1.0}`: A가 같은 행끼리 B의 합이 max 이하. `equals`와 `tolerance`도 쓸 수 있다
- `{"type": "lte", "left": "A", "right": "B", "why": "설명"}`: A ≤ B. `"skip_when_right_zero": true`를 주면 B가 0인 행은 건너뛴다 (구매가 0은 상점에서 팔지 않는 아이템)
- `{"type": "increasing", "order_by": "A", "column": "B"}`: A 순서로 정렬했을 때 B가 계속 증가
- `{"type": "contiguous", "column": "A"}`: A의 최소~최대 사이에 빠진 정수가 없음

## 언리얼 DataTable에서 CSV 내보내기

DataTable 에디터에서 CSV로 내보내면 첫 열(행 이름)의 머리글이 `---`로 나온다.
그 열을 키로 쓰려면 스키마에서 `"key": "---"`로 적고 `columns`에도 `"---"`를 넣는다.
