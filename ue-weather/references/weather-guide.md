## 1. 구조

```
서버: 지역별 날씨 상태와 전환 시각 결정 ──► 클라이언트: 파라미터를 목표 값으로 서서히 보간 ──► 각 시스템이 파라미터를 읽음
```

- **서버가 정한다.** 지역(존)마다 현재 날씨와 다음 날씨, 전환 시작 시각을 보낸다. 늦게 들어온
  플레이어도 같은 상태를 보도록 "지금 상태"를 접속 시 알려 준다.
- **클라이언트는 보간만 한다.** 날씨 관리자 하나가 파라미터 묶음을 현재 값에서 목표 값으로 옮긴다.
- **각 시스템은 파라미터만 본다.** 비 이펙트, 머티리얼, 안개, 바람, 소리가 날씨 이름이 아니라
  `rain_intensity`, `wetness` 같은 값을 읽는다. 그래서 새 날씨는 값 조합만 추가하면 된다.
- **시간대는 별도 축이다.** 낮/밤과 날씨를 한 상태로 묶지 않는다. 묶으면 조합 수만큼 상태가 늘어난다.

## 2. 파라미터

예시(규약의 `weather.params`):

| 파라미터 | 읽는 곳 |
|---|---|
| `rain_intensity` | 비 이펙트 스폰 양, 빗소리, 물웅덩이 |
| `snow_intensity` | 눈 이펙트 스폰 양 |
| `wind_speed` | 식생 흔들림, 이펙트의 바람, 망토와 깃발, 바람 소리 |
| `fog_density` | 높이 안개, 원경 가시거리 |
| `wetness` | 표면 머티리얼(어둡고 반짝이게), 캐릭터와 탈것 표면 |
| `snow_cover` | 표면 머티리얼(위를 향한 면에 눈), 발자국 |

- 모든 날씨가 같은 키를 가진다. 쓰지 않는 값은 0으로 넣는다.
- `wetness`와 `snow_cover`는 비나 눈이 그친 뒤 천천히 줄어야 자연스럽다. 강수량과 분리된 값으로 둔다.
- 머티리얼로 가는 값은 Material Parameter Collection 하나로 모은다. 머티리얼마다 따로 연결하지 않는다.

## 3. 구성 요소

| 요소 | 방법 | 5.8 참고 |
|---|---|---|
| 비, 눈 | Niagara 시스템이 카메라를 따라다니며 주변에만 내린다. 지역 전체에 뿌리지 않는다 | GPU 시뮬레이션. 실내 가림은 아래 참조 |
| 구름 | 볼류메트릭 클라우드의 덮임과 밀도를 파라미터로 조절 | MegaLights가 구름 그림자를 지원한다 |
| 안개 | 높이 안개의 밀도와 색 | 5.8에 안개 화면 공간 산란(FSSS)이 Experimental로 추가되어 짙은 안개와 연기가 부드럽게 섞인다 |
| 하늘과 조명 | 대기와 태양 강도, 색 | 흐린 날은 직사광을 낮추고 하늘빛을 올린다 |
| 번개 | 짧은 조명 섬광과 메시/이펙트, 지연된 천둥 소리 | 위치와 시각은 서버가 정할 필요가 없다. 연출이다 |
| 젖은 표면, 쌓인 눈 | 공통 머티리얼 함수가 `wetness`, `snow_cover`를 읽는다 | 모든 배경 머티리얼이 같은 함수를 쓰게 한다 |
| 바람 | 전역 바람 방향과 세기 | Procedural Vegetation Editor로 만든 식생은 바람에 반응한다(Experimental) |
| 소리 | 빗소리, 바람 소리의 음량과 필터 | 실내에서는 줄이고 걸러 낸다 |

**실내 처리:** 비와 눈이 지붕을 뚫고 내리면 안 된다. 실내 볼륨에 들어가면 강수 이펙트를 끄거나,
위에서 내려다본 깊이 정보로 가려지는 곳을 판정한다. 젖음과 눈 쌓임도 지붕 아래에서는 적용하지 않는다.

## 4. 게임플레이 연결

- **이동 모드 제한:** 폭풍에서 비행과 활공 금지처럼, 날씨가 이동 모드를 막을 수 있다(`blocked_modes`).
  판정은 서버가 한다. 날씨가 바뀌는 순간 이미 비행 중인 플레이어는 경고 후 강제 착륙시킨다.
  내려올 전환이 없으면 검사기가 `LINK010`으로 알려 준다.
- **바이옴:** 지역마다 나올 수 있는 날씨가 다르다(`biomes.weathers`). 사막에 눈이 오지 않게 한다.
- **전투와 스킬:** 날씨가 수치에 영향을 주면(비 오는 날 번개 피해 증가) 서버 데이터로 처리한다.
  클라이언트 파라미터로 계산하지 않는다.
- **NPC와 환경:** 비가 오면 NPC가 처마 밑으로 가는 식의 반응은 날씨 변경 알림을 받아 처리한다.

## 5. 성능

- 강수 이펙트는 화면에 하나만 띄운다. 규약에서 비용이 가장 큰 축에 속한다.
- 날씨 전환 중에는 이전 날씨와 다음 날씨의 이펙트가 겹친다. 그 구간을 측정한다.
- 젖은 표면은 반사를 늘려 GPU 비용이 오른다. 품질 옵션으로 낮출 수 있게 한다.
- 마을과 대규모 전투 장면을 맑은 날과 폭풍 양쪽으로 측정한다(`ue-perf-budget-check`).

## 6. 확장 지점

- **새 날씨(모래폭풍, 안개비):** 규약에 상태를 추가하고 파라미터 값을 넣고 전환을 연결한다.
  새 이펙트가 필요하면 `vfx`에 등록한다. 기존 시스템 코드는 고치지 않는다.
- **새 파라미터(모래 농도):** 모든 날씨에 값을 추가하고, 읽는 시스템을 만든다.
- **지역 한정 날씨:** 바이옴의 `weathers`로 제한한다.
- **날씨에 반응하는 파츠나 탈것:** 젖음 값은 캐릭터 머티리얼도 읽을 수 있다. 날씨 전용 파츠 이펙트는
  파츠 이펙트의 파라미터로 처리한다.

## 7. 체크리스트

- [ ] 날씨 상태를 서버가 정하고 접속 시 현재 상태를 알려 준다
- [ ] 모든 날씨가 같은 파라미터 키를 가진다
- [ ] 시스템들이 날씨 이름이 아니라 파라미터를 읽는다
- [ ] 강수 이펙트가 카메라 주변에만 있고 실내에서 가려진다
- [ ] 젖음과 눈 쌓임이 강수와 분리되어 서서히 변한다
- [ ] 이동 모드를 막는 날씨에 강제 착륙 처리가 있다
- [ ] 전환 구간과 폭풍 상태에서 프레임을 측정했다
- [ ] 규약 검사(`ue-client-contract`)를 통과했다
