# MMORPG 넷코드 가이드 (UE 5.8)

코드 리뷰나 설계 질문에 답할 때 읽는다. 프로젝트 결정 사항은 `mmorpg-router/references/project-context.md`가 우선한다.

## 목차

1. 원칙
2. 복제 시스템 선택 (5.8)
3. 프로퍼티 복제 체크리스트
4. RPC 체크리스트
5. 관심 영역 관리
6. 언리얼 복제에 싣지 않는 것

## 1. 원칙

- **서버가 결정한다.** 클라이언트는 의도(입력, 스킬 사용 요청)를 보내고, 결과(피해, 보상, 위치 확정)는 서버가 계산한다.
- **클라이언트가 보낸 값은 모두 의심한다.** 대상이 존재하는지, 사거리 안인지, 쿨다운이 끝났는지, 그 아이템을 실제로 가졌는지 서버 데이터로 확인한다.
- **필요한 사람에게 필요한 만큼만 보낸다.** MMORPG의 비용은 "플레이어 수 × 각자에게 보이는 대상 수"로 커진다.

## 2. 복제 시스템 선택 (5.8)

| 선택지 | 상태 | 비고 |
|---|---|---|
| 기본 복제 시스템 | 기본값 | 액터마다 관련성을 검사한다. 인원이 많아지면 서버 CPU가 먼저 한계에 닿는다 |
| Replication Graph | 지원 유지 | 공간 분할 노드로 대상 목록을 관리한다. Epic은 폐기 계획이 없다고 밝혔다 |
| Iris | 5.8에서 Production Ready, 직접 켜야 함 | 자체 필터링과 우선순위 체계를 쓴다. Replication Graph 노드 로직은 그대로 옮겨지지 않는다 |

결정할 때 확인할 것:

- Iris로 갈 경우 사용하는 플러그인(GAS, Mover, Network Prediction)과의 호환 상태를 해당 엔진 패치 버전 기준으로 확인한다. 5.7~5.8에서 GAS 태그 복제 관련 문제 보고가 있었다.
- Mass 엔티티 복제는 5.8에서 실험 단계다. 군중 NPC를 Mass로 만들 계획이면 복제는 별도 설계가 필요하다.
- 커스텀 `NetSerialize`를 쓰는 구조체는 Iris용 구현이 따로 필요하다.
- 시스템을 정하면 `project-context.md`에 기록한다. 리뷰 기준이 달라진다.

## 3. 프로퍼티 복제 체크리스트

- [ ] 복제가 꼭 필요한 값인가. 다른 복제 값에서 계산할 수 있으면 복제하지 않는다.
- [ ] 조건을 걸었는가. 인벤토리, 퀘스트, 재화는 `COND_OwnerOnly`. 다른 플레이어에게 보일 필요가 없다.
- [ ] 자주 바뀌지 않는 액터에 도먼시를 썼는가. 상자, 문, 채집물 등.
- [ ] `NetUpdateFrequency`를 액터 종류별로 정했는가. 모든 액터에 높은 값을 주지 않는다.
- [ ] Push Model을 쓰는가. 값이 바뀔 때만 더티 표시해 매 프레임 비교 비용을 없앤다.
- [ ] 큰 배열은 `FFastArraySerializer`인가.
- [ ] 벡터와 회전은 양자화 타입(`FVector_NetQuantize` 계열)을 썼는가.

## 4. RPC 체크리스트

- [ ] `Reliable`은 드물고 반드시 도착해야 하는 것에만 쓴다. 신뢰성 버퍼가 넘치면 접속이 끊긴다.
- [ ] Tick이나 입력 축 이벤트에서 `Reliable` RPC를 부르지 않는다.
- [ ] 연출용 `NetMulticast`는 `Unreliable`이다.
- [ ] `Server` RPC에 호출 빈도 제한이 있다. 초당 호출 수를 서버에서 세고 넘으면 버린다.
- [ ] `Server` RPC 구현부가 모든 인자를 검증한다.
- [ ] 상태는 RPC가 아니라 복제 프로퍼티로 전달한다. 늦게 들어온 플레이어는 지난 RPC를 받지 못한다.

## 5. 관심 영역 관리

- 관심 영역이 없으면 한곳에 N명이 모일 때 전송량이 N²으로 커진다.
- 보이는 플레이어 수에 상한을 둔다. 상한을 넘으면 거리, 파티/길드, 전투 관계 순으로 우선순위를 준다.
- 멀리 있는 대상은 갱신 빈도를 낮춘다.
- 마을, 공성전, 월드 보스처럼 사람이 몰리는 상황을 기준으로 설계한다. 평균이 아니라 최악을 본다.
- 수치 추정은 `mmo-server-capacity` 스킬로 한다.

## 6. 언리얼 복제에 싣지 않는 것

채팅, 길드, 우편, 경매장, 파티 매칭, 친구 목록, 랭킹은 존 서버를 넘나드는 기능이다.
게임플레이 복제가 아니라 별도 백엔드 서비스로 만든다. 존 서버가 죽어도 유지되어야 하기 때문이다.
