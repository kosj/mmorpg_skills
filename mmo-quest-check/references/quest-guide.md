## 1. 열 정의

`quests.csv`

| 열 | 형식 | 의미 |
|---|---|---|
| `id` | 문자열 | 퀘스트 ID |
| `name` | 문자열 | 이름 |
| `type` | main / side / daily | 종류 |
| `level_req` | 정수 | 받을 수 있는 최소 레벨 |
| `prev_quests` | `1\|2` | 선행 퀘스트 ID. 여러 개면 모두 완료해야 한다. 없으면 빈칸 |
| `objective_type` | kill / collect / talk / reach | 목표 종류 |
| `objective_target` | ID | kill은 몬스터 ID, collect는 아이템 ID. talk과 reach는 빈칸 |
| `objective_count` | 정수 | 목표 개수 |
| `reward_exp`, `reward_gold` | 정수 | 보상 |
| `reward_items` | `2001\|1009` | 보상 아이템 ID |

함께 읽는 표: `monsters.csv`(id, level, drop_group), `items.csv`(id, price_buy),
`drops.csv`(group_id, item_id, prob, min_count, max_count), `levels.csv`(level, exp_required. 없어도 된다).

## 2. 규칙 설명

| ID | 의미 | 결과 |
|---|---|---|
| QUEST001 | 형식 오류: ID나 이름 없음, ID 중복, 숫자가 아님, 알 수 없는 종류 | 서버가 퀘스트를 읽지 못하거나 다른 퀘스트를 덮어쓴다 |
| QUEST002 | 선행 퀘스트가 없는 ID이거나 자기 자신이다 | 그 퀘스트를 받을 수 없다 |
| QUEST003 | 선행 퀘스트가 돌고 돌아 서로를 요구한다 | 순환에 든 퀘스트와 그 뒤의 퀘스트 전부를 받을 수 없다 |
| QUEST004 | 선행 퀘스트의 요구 레벨이 이 퀘스트보다 높다 | 표시된 레벨에서 받을 수 없다. 요구 레벨을 맞추거나 선행 관계를 고친다 |
| QUEST005 | 처치 대상 몬스터나 수집 대상 아이템이 없다, 목표 개수가 1보다 작다 | 완료할 수 없거나 받자마자 완료된다 |
| QUEST006 | 수집 대상 아이템을 떨어뜨리는 몬스터도 파는 상점도 없다 | 완료할 수 없다 |
| QUEST007 | 처치 대상 몬스터의 레벨이 퀘스트 요구 레벨과 크게 다르다 | 너무 어렵거나 너무 쉽다. ID 오타일 수 있다 |
| QUEST008 | 보상 아이템이 없다 | 완료 시 서버 오류나 보상 누락 |
| QUEST009 | 이어지는 메인 퀘스트 사이의 레벨 차이가 크다 | 그 사이 레벨에서 메인 퀘스트가 끊긴다. 플레이어가 할 일을 잃는 지점 |
| QUEST010 | 보상 경험치가 그 레벨 필요 경험치의 큰 비중을 차지한다 | 퀘스트 하나로 레벨이 오른다. 자릿수 오타일 수 있다 |
| QUEST011 | 선행 메인 퀘스트가 없는 메인 퀘스트가 둘 이상이다 | 메인 줄기가 갈라져 있다. 선행 관계가 빠졌을 수 있다 |
| QUEST013 | 수집 퀘스트를 끝내려면 평균적으로 너무 많은 몬스터를 잡아야 한다 | 드롭 확률 대비 요구 개수가 과하다 |

수집 퀘스트의 필요 사냥 수 = 목표 개수 ÷ (그 아이템을 가장 잘 주는 몬스터의 마리당 기대 개수).
마리당 기대 개수 = 확률 × (최소 개수 + 최대 개수) ÷ 2.

## 3. 결과 읽는 법

- **레벨별 퀘스트 경험치 표:** 각 레벨에서 받을 수 있는 퀘스트(일일 제외)의 경험치 합과, 그 레벨을
  넘기는 데 필요한 경험치의 비율이다. 0%인 레벨은 사냥만으로 넘겨야 한다. 100%를 넘으면 퀘스트만으로
  레벨이 오르고 사냥터를 건너뛴다.
- **`QUEST003`의 경로:** `1 → 5 → 4 → 2 → 1`은 "1이 5를 요구하고, 5가 4를, 4가 2를, 2가 1을 요구한다"로
  읽는다. 이 중 하나의 선행 관계를 끊으면 풀린다.
- **`QUEST011`:** 의도적으로 줄기가 여럿인 구성(종족별 시작 퀘스트)이면 정상이다.

## 4. 검사가 보지 못하는 것

- NPC가 존재하고 맵에 배치되어 있는지, 도달 목표 지점이 갈 수 있는 곳인지
- 대상 몬스터가 맵에 실제로 배치되어 있는지, 리젠 속도가 충분한지
- 한 사냥터에 같은 대상을 노리는 퀘스트가 몰려 붐비는지
- 대사와 이야기의 흐름, 퀘스트 텍스트의 현지화
- 스크립트로 만든 특수 목표(호위, 제한 시간, 선택지)

## 5. 설계 원칙

- **퀘스트 상태는 서버가 가진다.** 클라이언트는 진행도를 표시만 한다. 완료 요청이 오면 서버가 목표
  달성과 보상 지급 가능 여부(가방 공간)를 확인한다.
- **보상은 한 번만 지급된다.** 완료 요청이 두 번 와도 한 번만 처리한다(`mmo-netcode-review`의 서버 검증).
- **선행 관계는 얕게 유지한다.** 깊은 사슬은 하나가 막히면 뒤가 전부 막힌다.
- **수집 퀘스트는 필요 사냥 수로 설계한다.** "아이템 10개"가 아니라 "평균 20마리"를 먼저 정하고
  확률과 개수를 맞춘다.
- **메인 퀘스트는 모든 레벨 구간에 걸쳐 이어지게 한다.** 끊기는 구간은 사이드 퀘스트나 사냥으로
  메울 수 있는지 `mmo-economy-check`의 레벨업 시간과 함께 본다.
- **퀘스트 전용 아이템은 상점 판매가를 0으로 둔다.** 팔 수 있으면 반복 퀘스트가 골드 수급처가 된다.

## 6. 확장 지점

- **새 목표 종류:** `quest-config.json`의 `objective_types`에 추가한다. 대상 검사가 필요하면
  `check()`의 목표 분기에 추가한다.
- **NPC와 위치 연결:** 스폰 데이터의 NPC ID를 읽어 퀘스트 시작/완료 NPC를 검사하는 규칙을 추가한다.
- **반복/일일 퀘스트의 골드 수급:** 하루에 얻을 수 있는 골드 합을 계산해 `mmo-economy-check`의
  시간당 골드와 비교한다.
- **분기 퀘스트:** 선행 조건이 "A 또는 B"이면 현재 형식(모두 완료)으로 표현되지 않는다. 열을 추가한다.
